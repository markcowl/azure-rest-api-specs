# Network ARM resource data assessment

This assessment covers the consolidated Network TypeSpec project in [Azure/azure-rest-api-specs#47722](https://github.com/Azure/azure-rest-api-specs/pull/47722) at source revision [`c09430b2a48b813af056e78c409af4d431f2dbc8`](https://github.com/Azure/azure-rest-api-specs/tree/c09430b2a48b813af056e78c409af4d431f2dbc8/specification/network/resource-manager/Microsoft.Network/Network/Network). The reports were generated with the ARM data exporter at [`8719b3d95d76a5b2144a3a5fcdcf184b665ebb6d`](https://github.com/Azure/typespec-azure/commit/8719b3d95d76a5b2144a3a5fcdcf184b665ebb6d), rebased on TypeSpec Azure main [`d1e6acc8738ce9684c5f51eee13bf6e05ac6b1d0`](https://github.com/Azure/typespec-azure/commit/d1e6acc8738ce9684c5f51eee13bf6e05ac6b1d0).

## Executive summary

- `resources.csv` contains **145 resolved resource occurrences** and **143 unique canonical resource keys**.
- `operations.csv` contains **752 resource-associated rows** representing **751 unique HTTP operations**. The extra row is the persistent duplicate `StaticCidrs.list` association.
- The unprojected service has **841 unique HTTP operations**. The **90 operations absent from `operations.csv`** are exactly **77 `providerOperations`** plus **13 operations carrying ARM operation metadata that appear in neither resolved-resource operations nor `providerOperations`**.
- Of the 77 provider operations, **49 are explicit ARM `list` operations for named resource models**. They are confirmed report omissions, but not resolver omissions: the resolver places them in `providerOperations`, and the emitter intentionally emits only operations attached to `provider.resources`.
- Of the remaining 28 provider operations without ARM resource metadata, **2 are likely missing child-resource associations** (`ExpressRouteLags.membersList` and `NetworkWatchers.connectionAnalyzersList`); **26 are expected provider-level catalog, discovery, availability, usage, check, or action endpoints**.
- The strongest missing resource declaration is [`ConnectionAnalyzer`](https://github.com/Azure/azure-rest-api-specs/blob/c09430b2a48b813af056e78c409af4d431f2dbc8/specification/network/resource-manager/Microsoft.Network/Network/Network/models.tsp#L28155): it is explicitly marked as a legacy custom Azure resource and has PUT/GET/DELETE/PATCH/list routes, but has no resolved row.
- The two resource-key collisions are an unexpected exact duplicate `ExpressRoutePort` occurrence and a real identity split for `StaticCidr`. Only the `StaticCidr.list` operation-key collision persists in every API-version projection.
- Latest-main output has the same 145/752/841 counts as the PR-pinned dependency baseline. The newer exporter changes provenance and validation, not Network resolver coverage.

## Methodology

1. Compiled [`main.tsp`](https://github.com/Azure/azure-rest-api-specs/blob/c09430b2a48b813af056e78c409af4d431f2dbc8/specification/network/resource-manager/Microsoft.Network/Network/Network/main.tsp), which imports `client.tsp`, with TypeSpec 1.18.0 and zero compiler diagnostics.
2. Overlaid the built latest-main `package.json` and `dist` artifacts for `@azure-tools/typespec-data-exporter`, `@azure-tools/typespec-arm-resource-data`, and `@azure-tools/typespec-azure-resource-manager`. The project's installed Azure Core package was compatible, so no Azure Core overlay was used.
3. Generated the CSVs with source URL expansion pinned to the PR head and the full project-relative path.
4. Compared `resolveArmResources` output with all operations from `getAllHttpServices`, ARM operation metadata from `getArmResourceOperationData`, `@armResourceOperations` interfaces, lifecycle/list/action templates, and literal routes in the project.
5. Checked resource and operation canonical keys, duplicate groups, exact emitter sorting (`localeCompare`), source-link revision/path validity, and all six API-version projections (`2025-05-01` through `2026-05-01`).
6. Treated names alone as insufficient evidence. A model is listed as a likely missing resource only when it also has an addressable ARM-shaped instance route and lifecycle/read/list evidence. Provider catalogs and action-result models were excluded.

## Conclusion

The CSVs accurately represent the current emitter contract, not the full Network HTTP surface. The highest-priority resolver follow-ups are the duplicate/split `ExpressRoutePort` and `StaticCidr` identities, the explicitly declared `ConnectionAnalyzer` resource, the resource-shaped child CRUD/list groups in the candidate table, and the 12 resource-related operations among the 13 ARM-metadata operations outside both resolver buckets. The 49 provider resource lists are complete resolver data that the current emitter intentionally excludes; changing that requires an explicit contract decision rather than a Network-spec fix.
