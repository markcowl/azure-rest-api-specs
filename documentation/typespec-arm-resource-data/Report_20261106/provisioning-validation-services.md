## Methodology

- Report source: `Azure/azure-rest-api-specs@25e6580ed12cabbca57863ab3c2b13b6657dfa0e`.
- Correlation first uses the ARM provider namespace directory (for example, `Microsoft.ServiceBus`), then the final directory containing `tspconfig.yaml`, and finally the outer specification service directory or explicit generated-client alias when SDK and TypeSpec names differ.
- A service qualifies only when its correlated report project succeeded, its `resources.csv` contains at least one resource, and the project has no duplicate-resource or resource-name-clash groups.
- SDK resource counts in the issue comment are not used as a qualification test; this report evaluates the resolver output and problem categories in `Report_20261106`.
- Every input service appears exactly once in one of the two tables below.
